## What This Project Is

**AI Video Production Hub** — a self-hosted web app that turns prompts or a narration script into a finished short-form video. Finished videos can optionally be uploaded to NextCloud (public share link) and mirrored into NocoDB.

**Two production modes:**

1. **Prompt-pack pipelines** — the user pastes or drops a prompt pack on the New pack page (`/new`). `frontend/src/lib/promptPackParser.js` extracts image/video prompts and picks the mode:
   - `veo31_frame` (frame mode): N images + N-1 videos (chain), N images + N videos (chain + hero reveal), or 2N images + N videos (paired first/last frame per scene).
   - `grok_sequential_extend` (extend mode): 1 image + ≥1 videos; one clip is generated then extended (Grok or Veo 3.1 engine).
   - Images are generated sequentially, each using the previous image as reference (SnapGen → Kie.ai → fal.ai fallback; providers without keys are skipped). Video is SnapGen only (Veo 3.1, Grok). Clips are combined with FFmpeg.
2. **Script Studio** — narration script → ElevenLabs TTS via fal.ai (Kie.ai fallback) → OpenRouter LLM splits script into scenes and writes all scene image prompts in one batched call → scene images (fal.ai model picker, or SnapGen / Kie.ai) → Ken Burns clips → karaoke ASS subtitles (active word yellow) → optional background-removed watermark → final FFmpeg mux.

There is **no category system** (an older version had one; `backend/categories/` does not exist). Prompts arrive fully written in the pasted pack or are generated by Script Studio.

**Stack & layout:**
- `backend/app/` — FastAPI package: `config.py` (env), `auth.py` (password login → signed bearer tokens, required on every `/api` route except health/login), `api.py` (routes), `views.py` (response shaping, `steps[]`), `providers/` (SnapGen — formerly GeminiGen, OpenRouter, fal.ai, Kie.ai, image fallback chain), `integrations/` (NextCloud, NocoDB — both optional), `pipelines/` (`runner.py` task registry + pause/cancel, `pack.py`, `script.py`).
- `backend/server.py` — thin entry so `uvicorn server:app` works. `backend/database.py` — SQLite (`DATA_DIR`), additive migrations only. `backend/script_studio.py` — TTS, subtitles, FFmpeg helpers.
- `backend/tests/` — pytest suite (`cd backend && uv run pytest -q`). Provider calls are mocked; never hit paid APIs in tests.
- `frontend/` — React + Vite + Tailwind. Routes: `/` queue, `/new` prompt-pack editor, `/script` Script Studio, `/run/:id` run detail. All API calls go through `src/lib/api.js`.
- `Dockerfile` + `deploy/` + `docker-compose.yml` — single image (nginx + supervisord + ffmpeg + uvicorn as non-root). All persistent state under `/app/data`.

## Writing Prompt Packs

When generating a prompt pack (for the user to paste into the New pack page), follow these rules — they are what keeps a sequence visually consistent:

1. **SCENE LOCK** — every image prompt opens with the same fixed camera setup (position, angle, lens), verbatim.
2. **CHARACTER / ENVIRONMENT LOCK** — define each character and location fully the first time, then repeat those exact details verbatim every time they reappear.
3. **Sequence continuity** — each frame follows logically from the previous (time of day, object states, positions).
4. **First and last frame** — frame 1 is the rawest/starting state; the final frame is the fully resolved state with nothing unfinished.
5. **Detail floor** — ≥150 words per image prompt, ≥100 words per video prompt.
6. **PROMPT PURITY** — never write `NEGATIVE:` blocks or "no X" prohibition lists. Image/video models read all text as positive description, so "no split image" produces split images. Describe only what IS present. (The backend strips NEGATIVE blocks as a safety net, but don't rely on it.)
7. **Shape** — output must match one of the parser shapes above, labelled `Image 1:` / `Video 1:` or as JSON `{"image_prompts": [...], "video_prompts": [...]}`.

Per-channel style recipes live in `directives/styles/<slug>.md` (see `directives/clone_channel_style.md`).

## The 3-Layer Architecture

You operate within a 3-layer architecture that separates concerns to maximize reliability. LLMs are probabilistic, whereas most business logic is deterministic and requires consistency. This system fixes that mismatch.

**Layer 1: Directive (What to do)**
- SOPs written in Markdown, live in `directives/`
- Define the goals, inputs, tools/scripts to use, outputs, and edge cases

**Layer 2: Orchestration (Decision making)**
- This is you. Read directives, call execution tools in the right order, handle errors, ask for clarification, update directives with learnings.

**Layer 3: Execution (Doing the work)**
- Deterministic Python scripts in `execution/` (currently: `scrape_social_page.py`, `download_videos.py`, `analyze_videos.py`)
- Environment variables and API tokens are read from `.env` (never read or edit it — see global rules; add new keys to `.env.example`)

**Why this works:** if you do everything yourself, errors compound. 90% accuracy per step = 59% success over 5 steps. Push complexity into deterministic code and focus on decision-making.

## Operating Principles

**1. Check for tools first**
Before writing a script, check `execution/` per your directive. Only create new scripts if none exist.

**2. Self-anneal when things break**
- Read the error message and stack trace
- Fix the script and test it again (unless it uses paid tokens/credits — SnapGen, OpenRouter, fal.ai, Kie.ai, Apify, Gemini all do — in which case check with the user first)
- Update the directive with what you learned (API limits, timing, edge cases)

**3. Update directives as you learn**
Directives are living documents. When you discover API constraints, better approaches, common errors, or timing expectations — update the directive. Don't create or overwrite directives without asking unless explicitly told to.

## File Organization

**Deliverables vs Intermediates:**
- **Deliverables**: the finished video (NextCloud share link when configured, otherwise served by the app) and its NocoDB record when configured
- **Intermediates**: scraped metadata, downloaded reference videos, analysis files, render work dirs

**Directory structure:**
- `.tmp/` — all intermediate files. Never commit, always regenerated.
- `execution/` — Python scripts (the deterministic tools)
- `directives/` — SOPs in Markdown (the instruction set)
- `.env` — environment variables and API keys (user-maintained, gitignored)

## Summary

You sit between human intent (directives) and deterministic execution (scripts + the app). Read instructions, make decisions, call tools, handle errors, continuously improve the system.

Be pragmatic. Be reliable. Self-anneal.
